# Foundation integration plan

DEV and PROD use separate S3 backend keys (`foundation/terraform.tfstate`) and
Sydney providers. DEV is enabled only with approved identity, CIDR, AZ, role,
retention, and budget inputs. PROD has `enable_deployment=false` by default;
no production resources are authorized in Phase 1.

Plan evidence must be generated by an approved operator after dependency
initialization. This repository does not contain or fabricate plan JSON. The
read-only sequence is `terraform init -backend=false` followed by reviewed
`terraform plan -out=foundation.tfplan` and JSON inspection. No apply is
permitted before P1-CP1 Human approval.

Expected code-level DEV topology is 76 foundation instances plus 9 bootstrap
instances; PROD is zero actions by default. Actual counts must be derived from
the reviewed plan manifest, not assumed from this document.

The machine-readable contract is `tests/infrastructure/approved-plan-manifest.json`.
After an approved operator creates `terraform show -json` output, validate it
with `validate-plan.ps1 -Environment dev -PlanJson <path>` or the Bash parity
script. DEV permits exactly 76 approved creates and no update/delete/replace;
PROD permits zero resource changes. Plan JSON is sensitive and is not committed.

Phase 1 cost remains the approved USD 4–12/month planning range, including
three KMS keys, low-volume S3, CloudTrail/log requests, and SNS requests. Any
additional endpoint, compute, or retention cost requires re-estimation.

The three fixed KMS components are state bootstrap, platform data, and audit
encryption (approximately USD 1/month each before requests). Foundation has 76
instances, bootstrap has 9, and PROD has 0.

Rollback is a reviewed Terraform state operation: preserve versioned state,
reverse dependencies, and never bypass `prevent_destroy` without explicit
Human approval. Bootstrap state recovery uses prior S3 versions and lock
contention investigation.

Actual plan execution is **NOT RUN**. Terraform 1.16.1 and the signed HashiCorp
AWS provider 6.63.0 are initialized locally; both DEV roots pass real
`terraform validate` and recursive formatting checks. The remaining blocker is
the AWS identity boundary: the Codex process has no AWS session, and the
Human-reported root session is explicitly prohibited as a Terraform execution
identity. Plan review still requires read-only discovery through an approved
non-root short-lived session, explicit existing role ARNs, a conflict-checked
VPC CIDR, and a Human-approved state noncurrent-version retention value.
